# ADR 0005: Three key backends, with `app-encrypted` protection by default

## Status

Accepted

## Context

CA keys must be usable by Lambda, cheap, and as protected as the deployer can afford. KMS keys are
non-exportable and the strongest, but cost money and support only RSA 2048/3072/4096 and ECC
P-256/384/521. Parameter Store SecureString is free but a parameter encrypted with the AWS-managed
key can be read in clear by anyone who can read the parameter, in the console. Secrets Manager is in
between on cost.

Systems Manager also rejects parameter names that start with `aws` or `ssm` (any case). This was
found by the first run against real AWS, because a mocked SSM accepts any name.

## Decision

Each CA has a key store `{ backend, protection }`:

- `backend` is `parameter`, `secret` or `kms`. KMS means a non-exportable asymmetric signing key;
  every CA signature is a `kms:Sign` (hashed locally and signed as a digest, because `RAW` is limited
  to 4096 bytes).
- For `parameter` and `secret`, the value is PKCS#8 protected according to `protection`:
  `aws-managed-key`, `app-encrypted` (**default**: AES-256-GCM with a key from HKDF over a random
  encryption secret) or `customer-managed-key` (a KMS key whose policy allows decrypt only to the
  Lambda role).
- The encryption secret is generated by the bootstrap and kept in a separate SecureString under
  `<prefix>/internal/`. It is never in the Lambda environment, the CloudFormation template or CDK
  context.
- `namePrefix` defaults to `/private-ca`, and both configuration and key store refuse a reserved
  prefix.

Signing goes through a `Signer` interface; a `CryptoKey`-shaped adapter lets `@peculiar/x509` sign
with `kms:Sign`.

## Consequences

The free default is better than a plain SecureString, but `app-encrypted` only defeats casual
console browsing; it is not a substitute for `customer-managed-key` or `kms`, and the documentation
says so. The encryption secret cannot be rotated, because stored keys are encrypted under it;
rotation means adding new CAs. KMS CAs are restricted to KMS algorithms, and a KMS root cannot be
taken offline. The hardcoded pepper of the previous implementation is gone.
